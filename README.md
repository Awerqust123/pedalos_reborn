# PedalosTeam — система керування командою

Сайт, через який керівництво бачить, на якій стадії кожен розділ, хто що робить, що відстає і які дедлайни. Куратори тайтлів шукають людей на біржі, а виконавці бачать свої завдання й подають на підвищення рангу.

> **Статус:** перша робоча версія. Код перевірено на синтаксис, база перевірена на локальному Postgres, але в живому браузері сайт ще проходить тестування. Вхід через Discord і бот ще не зроблені (див. розділ «Що не готово»).

## 1. З чого складається

| Частина | Що це |
|---|---|
| `index.html`, `app.js`, `style.css` | Сайт: звичайний JS без збірки, працює на GitHub Pages |
| `config.js` | Адреса Supabase і публічний ключ (безпечні для GitHub) |
| `db/pedalos_schema.sql` | Уся база: таблиці, правила доступу, автоматика |
| `db/pedalos_migration_001.sql` | Доповнення: коментарі, самозапис, повернення на етап (виконати **після** схеми) |
| `db/pedalos_migration_002.sql` | Аватарка профілю й підготовка до Discord (виконати після 001) |
| `db/pedalos_migration_003.sql` | Куратори напряму приймають новачків (виконати після 002) |
| `db/pedalos_migration_004.sql` | Завершення навчання й видалення акаунта учня (виконати після 003) |
| Supabase | База даних, вхід (Auth), правила доступу (RLS) |

**Секретний ключ (`service_role` / secret) ніколи не кладемо в репозиторій.** Вся безпека тримається на правилах доступу в базі, а не на прихованому коді сайту.

### Запуск з нуля
1. Створи проєкт на supabase.com.
2. SQL Editor → встав `pedalos_schema.sql` → Run, потім так само `pedalos_migration_001.sql` `pedalos_migration_002.sql`, `pedalos_migration_003.sql` і `pedalos_migration_004.sql` (строго по порядку; без них не працюватимуть коментарі, «Взяти», «Повернути», «Новачки»).
3. Заповни `config.js` (Project Settings → API: `Project URL` без `/rest/v1/` і публічний ключ).
4. Authentication → Providers → Email: для тестів вимкни «Confirm email».
5. Залий файли на GitHub, Settings → Pages → Deploy from branch (`main`, root).
6. Authentication → URL Configuration: встав адресу сайту в Site URL і Redirect URLs.
7. Зареєструйся на сайті, потім виконай у SQL Editor блок «Перший адмін» з кінця схеми (підстав свій email). Після цього з'явиться вкладка «Люди».

Локальний тест без GitHub: відкрий `index.html` з диска або запусти `python -m http.server 8000` у папці сайту.

## 2. Як влаштована робота над розділом

Кожен розділ має 5 етапів. Вони створюються автоматично разом із розділом.

```
Переклад ─┐
          ├─ Переклад → Редакт ─┐
Клін ─────┘                     ├─→ Тайп → QC → Куратор підтверджує → Аплоадер викладає
          Клін ─────────────────┘
```

- **Переклад і клін** стартують одночасно.
- **Редакт** відкривається, коли готовий переклад.
- **Тайп** відкривається, коли готові і редакт, і клін.
- **QC** відкривається після тайпу.
- Коли QC завершив, розділ переходить у статус «перевірка куратора». Куратор тайтла натискає «Підтвердити розділ», розділ стає «готовим до заливу».
- Аплоадер позначає розділ «викладеним» (можна додати посилання).

Статуси етапу: `чекає` → `можна брати` → `в роботі` → `готово`. Розблокування робить сама база.

### Дедлайни
Один дедлайн на розділ (тиждень, місяць, як вирішить куратор). Дедлайнів на етапах немає. У базі є необов'язкове поле для орієнтовних дедлайнів етапів, інтерфейс для нього ще не зроблений.

Статус розділу на дашборді:
- **прострочено** — дедлайн минув, а розділ не викладено;
- **під ризиком** — час спливає помітно швидше, ніж рухається робота (різниця понад 25% між часткою вичерпаного часу і часткою виконаних етапів);
- **ок** — решта.

## 3. Ролі

### Службові ролі
| Роль | Що вміє |
|---|---|
| **Керівництво** | Повний доступ: тайтли, розділи, люди, ролі, активація акаунтів |
| **Розробка** | Ті самі права, що й у керівництва (для людей, які розвивають сайт і системи) |
| **Аплоадер** | Позначає підтверджені розділи як викладені. Окрема роль, не змішується з куратором (одна людина може мати обидві) |
| **Куратор тайтла** | Призначається на конкретні тайтли (одного або кількох). Керує розділами тайтла, призначає виконавців, підтверджує розділи, публікує вакансії на біржі, розглядає заявки |

### Робочі ролі
| Роль | Етап |
|---|---|
| Перекладач | Переклад |
| Редактор | Редакт |
| QC (бета-рідер) | QC |
| Клінер ЧБ (манга) / Клінер колір (манхва) | Клін |
| Тайпер ЧБ (манга) / Тайпер колір (манхва) | Тайп |

Тип тайтла (манга чи манхва) визначає, яка версія ролі потрібна: у манги ЧБ-клінер і ЧБ-тайпер, у манхви кольорові.

### Як приймаються новачки
Людина реєструється на сайті, і її акаунт чекає. Куратори напряму та керівництво бачать у меню вкладку **«Новачки»** з лічильником. Там два варіанти:
- **«Прийняти учнем»**: відкриває доступ і ставить людину учнем у вибраному напрямі. Наставником стає куратор напряму (той, хто приймає).
- **«Лише відкрити доступ»**: доступ є, а роль видасть керівництво.

**Учні за напрямами.** У тій самій вкладці «Новачки та учні» нижче є список учнів, згрупований за напрямами, з наставником і кількістю виконаних етапів. Усі куратори бачать усі напрями, але діяти з учнем може лише його наставник (і керівництво):
- **«Завершити навчання → C»** знімає статус учня й дає ранг C у тому самому напрямі.
- **«Видалити акаунт»** назавжди видаляє акаунт того, хто не закінчив навчання (лише якщо всі його ролі учнівські).

Куратор може приймати лише у **свої** напрями й лише акаунти без жодної ролі, тобто не може повернути доступ тому, кому його вимкнуло керівництво. Вимикати доступ і видавати ранги може лише керівництво (ранги ще через запити на підвищення).

### Рівні всередині робочої ролі
- **Учень (новачок)** — ранг ще немає. За учнем закріплений наставник (один із кураторів). Спочатку учень робить тести з наставником. Згодом позначка «учень» лишається як сигнал, що це свіжа кров і за людиною треба дивитись.
- **Ранг C → B → A → S** — показник навичок. Також орієнтир для кураторів і фільтр на біржі.
- **Куратор напряму** (наприклад, куратор ЧБ-тайпу) — доступний **тільки з рангом A або S** (мінімум налаштовується окремо для кожної ролі, зараз A). Куратор напряму розглядає запити на підвищення і задає правила підвищення для своєї ролі.

### Як отримати роль
| Що | Хто видає | Як |
|---|---|---|
| Доступ до сайту | Куратор напряму або керівництво | Людина реєструється, її приймають у вкладці «Новачки» (див. нижче) |
| Робоча роль, учень, наставник | Керівництво | «Люди» → «+ роль» |
| Ранг C/B/A/S | Куратор ролі або керівництво | Людина подає запит у «Профілі», куратор схвалює |
| Куратор напряму | Керівництво | «Люди» → «+ роль» з галочкою «куратор напряму» (тільки з рангом A/S) |
| Куратор тайтла | Керівництво | Сторінка тайтла → «Додати куратора» |
| Аплоадер, керівництво, розробка | Керівництво | «Люди» → «+ роль» |
| Місце в команді тайтла | Куратор тайтла | Біржа: заявка → «Прийняти» |

### Підвищення рангу
1. У «Профілі» людина бачить вимоги на наступний ранг і свій прогрес.
2. Коли всі вимоги виконані, зʼявляється кнопка «Подати запит».
3. Куратор цієї ролі (або керівництво) схвалює або відхиляє. Свій запит розглядати не можна.
4. Куратори **самі змінюють правила** підвищення для своєї ролі в блоці «Куратору напряму».

**Що рахується:** кількість етапів, завершених саме цією роллю на сайті (для ЧБ і кольору — за типом тайтла), і кількість днів у команді. Історія рахується від запуску сайту.

#### Приклад вимог (умовні значення, куратори змінять)
| Перехід | Розділів | Днів у команді | Додатково (текст) |
|---|---|---|---|
| Учень → C | 5 | 14 | Пройти тестове завдання з наставником |
| C → B | 15 | 60 | Мінімум помилок за відгуками QC |
| B → A | 40 | 120 | Стабільно здавати в дедлайн |
| A → S | 100 | 270 | Рекомендація від 2 кураторів ролі |

Правило без заданих вимог означає нуль розділів і нуль днів, тобто пройти може кожен. Тому правила варто виставити одразу.

## 4. Що можна робити на сайті

### Для всіх
- **Вхід і реєстрація** по email і паролю. Новий акаунт нічого не бачить, поки його не активує керівництво.
- **Дашборд:** лічильники (прострочено, під ризиком, чекають куратора, готові до заливу) і таблиця активних розділів з крапками етапів, дедлайном і статусом. Найпроблемніші угорі.
- **Тайтли:** список і сторінка тайтла з розділами та кураторами.
- **Розділ:** статуси етапів, виконавці, дедлайн.
- **Мої завдання:** усі етапи, призначені мені, з кнопками «Почати» і «Готово».
- **Біржа:** вакансії, відгук із короткою приміткою. Кнопка відгуку є лише в тих, у кого є така роль і достатній ранг. Видно статус своєї заявки.
- **Профіль:** мої ролі та ранги, наставник, вимоги на наступний ранг, подача й скасування запиту на підвищення.
- **Мобільна версія:** меню в один рядок, таблиці перетворюються на картки, великі кнопки й поля.

### Додатково (версія 2)
- **Нова навігація:** тонка верхня панель, праворуч аватарка з меню (Профіль, Вийти; на телефоні ще «Команда» і «Люди»). На телефоні нижня панель вкладок: Дашборд, Тайтли, Завдання, Біржа.
- **Вхід і реєстрація** розділені на два режими з підписом у формі; поле «Імʼя» є лише в реєстрації, помилки показуються українською, введені дані не зникають.
- **Аватарка:** у профілі є поле `avatar_url`. Коли підключимо Discord, нікнейм і фото підтягуватимуться звідти.
- **Фільтри дашборда:** пошук за тайтлом чи номером розділу, фільтри за тайтлом, статусом (прострочено, під ризиком, чекають куратора, готові до заливу) і виконавцем.
- **Масове додавання розділів:** `15`, `15-20` або `15,17,20-22`; необов'язково перший дедлайн і крок у днях між дедлайнами.
- **Посилання на файли (Drive)** на кожному етапі.
- **«Повернути»** (QC, куратор тайтла, керівництво): етап знову стає доступним із коментарем, що виправити, усі наступні етапи чекають, розділ знову «у роботі».
- **Коментарі** до розділу або до конкретного етапу.
- **Журнал змін розділу:** хто, коли й що зробив (статуси, виконавці, підтвердження, публікація).
- **«Команда»:** навантаження кожної людини: активні етапи, в роботі, прострочені, зроблено за 30 днів.
- **Самозапис:** кнопка «Взяти» на вільному етапі й розділ «Вільні завдання для тебе» у «Мої завдання». Показуються лише етапи, що підходять за роллю й типом тайтла. Учні самі не беруть, їх ставить куратор. Є й «Відмовитись».

### Для кураторів тайтла
Створювати й видаляти розділи (з підтвердженням), ставити дедлайни, призначати виконавців на етапи (показуються тільки люди з відповідною роллю), підтверджувати розділи, публікувати вакансії, приймати чи відхиляти заявки (прийнятий автоматично потрапляє в команду тайтла), закривати вакансії.

### Для аплоадерів
Позначати розділи викладеними з посиланням.

### Для кураторів напряму
Розглядати запити на підвищення у своїй ролі та редагувати правила підвищення.

### Для керівництва і розробки
Усе вище плюс: створення тайтлів, вкладка «Люди» (активація акаунтів, видача й зняття ролей, рангів, позначок учня, наставників, куратора напряму), призначення кураторів тайтлів.

## 5. База даних коротко

- **Люди:** `profiles`, `roles`, `user_roles` (роль + ранг + учень + наставник + куратор напряму).
- **Тайтли й розділи:** `titles`, `title_members`, `chapters`, `chapter_stages`, `chapter_events` (журнал змін).
- **Біржа:** `job_postings`, `job_applications`.
- **Підвищення:** `promotion_rules`, `promotion_requests`.
- **Для майбутнього Discord:** `discord_role_map`, поля `discord_id` і `telegram_id` у профілі.
- **Автоматика:** створення етапів, розблокування ланцюжка, журнал змін, обмеження «куратор тільки з рангом A/S», перевірка вимог на підвищення.
- **Безпека:** правила доступу (RLS) на кожній таблиці, критичні дії (підтвердження, публікація, прийняття заявки, підвищення) виконуються тільки через захищені функції.

## 6. Що не готово та відомі обмеження

- **Вхід через Discord і бот:** підтягування ролей із сервера, дублювання біржі в канал, приватний канал для підвищення. Таблиця зіставлення ролей уже є. Коли ролі братимуться з Discord, схвалення підвищення має ще й міняти роль на сервері.
- Немає сповіщень (нагадування про дедлайни, повідомлення виконавцям).
- Повторне відкриття завершеного етапу не повертає наступні етапи в очікування.
- Якщо дія заборонена правилами доступу, сайт може просто нічого не змінити без повідомлення.
- Облікові записи створюються самореєстрацією з активацією керівництвом (сервера для створення акаунтів немає).
- Зі старої бази нічого не переносилось: там були лише тестові записи.

## 7. Варіанти розширення

**Швидкі (зроблені у версії 2: фільтри, масове додавання, файли, повернення на етап, коментарі, навантаження, журнал, самозапис)**
- Усе вище вже реалізовано.

**Середні**
- Сповіщення в Discord або Telegram: нагадування про дедлайн, «ваш етап відкрився», «розділ готовий до заливу».
- Календар дедлайнів.
- Статистика: хто скільки розділів зробив за місяць, середній час етапу, скільки розділів вчасно, таблиця активності.
- Картка тайтла: обкладинка, опис, посилання на оригінал, графік виходу, статус (активний, на паузі, завершений).
- Автоматичний розрахунок орієнтовних дедлайнів етапів від кінцевого дедлайну.
- Кілька тестових завдань для учнів із відмітками наставника.
- Режим PWA: сайт додається на головний екран телефону як застосунок.

**Великі**
- Повна інтеграція з Discord: вхід, ролі, біржа в каналах, приватні канали підвищення, команди бота.
- Телеграм-бот як другий інтерфейс.
- Нагадування про простій: «етап стоїть без руху понад N днів».
- Облік виплат або внесків, якщо в команді це актуально.
- Публічна сторінка команди зі списком релізів.
- Експорт звітів (CSV) для керівництва.
